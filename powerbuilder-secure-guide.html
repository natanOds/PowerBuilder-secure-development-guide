01

Always use AES in a secure cipher mode

● HIGH

AES supports multiple modes of operation. ECB (Electronic Codebook) is deterministic — identical plaintext blocks produce identical ciphertext blocks — making it trivially vulnerable to pattern analysis. Always prefer GCM (authenticated encryption) or, if unavailable, CTR with a unique nonce. Avoid ECB entirely and be cautious with CBC if IV management is not handled correctly.

Non-compliant 
// ECB mode — never use
loo_Crypt = create oleobject
loo_Crypt.CryptAlgorithm = "aes"
loo_Crypt.CipherMode = "ecb"

// CBC without proper IV handling
lblb_encrypt = lnv_Crypt.SymmetricEncrypt( &
  AES!, lblb_data, lblb_key, &
  OperationModeCBC!, lblb_iv, PKCSPadding!)
Compliant 
// CTR mode with NoPadding
lblb_encrypt = lnv_Crypt.SymmetricEncrypt( &
  AES!, lblb_data, lblb_key, &
  OperationModeCTR!, lblb_iv, NoPadding!)

// Prefer GCM when available —
// provides authentication + encryption
02

Never use console logging in production

● MEDIUM

Console output via WriteConsole (Kernel32.dll) must be disabled in production builds. Console logs can expose sensitive data — user input, tokens, internal state — and reveal implementation details that aid attackers in reconnaissance.

Non-compliant 
// Direct write to console — exposes internals in production
FUNCTION ulong WriteConsole( &
  long Handle, String OutPut, &
  long NumCharsToWrite, &
  REF long NumCharsWritten, &
  long reserved) &
  LIBRARY "Kernel32.dll" ALIAS FOR "WriteConsoleW"
03

Do not use CoSetProxyBlanket or CoInitializeSecurity

● HIGH

Calls to CoSetProxyBlanket, CoInitializeSecurity, and their aliases can downgrade COM security settings — potentially disabling authentication, integrity checks, or encryption on DCOM calls. Remove all direct calls to these functions from PowerBuilder code.

Non-compliant 
SUBROUTINE CoInitializeSecurityAlias(string uExitCode) &
  LIBRARY "ole32.dll" ALIAS FOR "CoInitializeSecurity"

SUBROUTINE CoInitializeSecurity(string uExitCode) &
  LIBRARY "ole32.dll"

SUBROUTINE CoSetProxyBlanket(string uExitCode) &
  LIBRARY "ole32.dll"
04

Cryptographic keys must meet minimum length requirements

● HIGH

Short keys are vulnerable to brute-force attacks. Follow NIST SP 800-57 recommendations: RSA keys must be at least 2048 bits (3072+ preferred for new systems). Keys below 2048 bits provide insufficient security margin with current computational capabilities.

Non-compliant 
CrypterObject lnv_CrypterObject
lnv_CrypterObject = Create CrypterObject
li_return = lnv_CrypterObject.AsymmetricGenerateKey( &
  RSA!, 1024, lblb_privKey, lblb_pubKey)
// 1024-bit RSA — insufficient
Compliant 
CrypterObject lnv_CrypterObject
lnv_CrypterObject = Create CrypterObject
li_return = lnv_CrypterObject.AsymmetricGenerateKey( &
  RSA!, 2048, lblb_privKey, lblb_pubKey)
// 2048-bit minimum (NIST recommendation)
05

Database queries must not be vulnerable to SQL injection

● HIGH

PowerBuilder applications are typically database-intensive and mission-critical. String concatenation to build SQL queries is the primary vector for SQL injection — allowing attackers to read, modify, or delete data, or take control of the database server. Always use parameterized queries via PREPARE / EXECUTE or dynamic cursors.

Non-compliant — string concat 
// SQL injection via concatenation
string query = "DELETE FROM employee " &
  + "WHERE emp_id = '" &
  + Emp_id_var + "'"
EXECUTE IMMEDIATE :query

string query = "SELECT emp_id FROM employee " &
  + "WHERE state = '" &
  + Emp_state_var + "'"
EXECUTE IMMEDIATE :query
Compliant — parameterized 
// Parameterized DELETE
PREPARE SQLSA
  FROM "DELETE FROM employee WHERE emp_id = ?"
EXECUTE SQLSA USING :Emp_id_var

// Parameterized SELECT with dynamic cursor
PREPARE SQLSA
  FROM "SELECT emp_id FROM employee WHERE state = ?"
OPEN DYNAMIC my_cursor USING :Emp_state_var
FETCH my_cursor INTO :Emp_id_var
CLOSE my_cursor
06

DES and 3DES must not be used

● HIGH

DES uses a 56-bit key and has been considered broken since the late 1990s. 3DES (Triple DES) is deprecated by NIST as of 2023 and is vulnerable to the SWEET32 birthday attack at practical data volumes. Replace all usages with AES-256.

Non-compliant 
// OLE object approach — DES forbidden
loo_Crypt = create oleobject
loo_Crypt.CryptAlgorithm = "des"

// CrypterObject approach — also forbidden
lblb_encrypt = lnv_CrypterObject.SymmetricEncrypt( &
  DES!, lblb_data, lblb_key, &
  OperationModeCBC!, lblb_iv, PKCSPadding!)
07

Use correct cipher mode and padding scheme combinations

● HIGH

Not all combinations of cipher mode and padding scheme are valid or secure. In particular, CBC mode requires PKCS padding — but CBC itself is susceptible to padding oracle attacks if error handling is not carefully implemented. CTR mode is a stream cipher and must use NoPadding; applying block padding to CTR is incorrect and produces malformed output.

Non-compliant 
// CTR + PKCSPadding — invalid combination
lblb_encrypt = lnv_CrypterObject.SymmetricEncrypt( &
  AES!, lblb_data, lblb_key, &
  OperationModeCTR!, lblb_iv, PKCSPadding!)
Compliant 
// CTR + NoPadding — correct
lblb_encrypt = lnv_CrypterObject.SymmetricEncrypt( &
  AES!, lblb_data, lblb_key, &
  OperationModeCTR!, lblb_iv, NoPadding!)
08

Generic exceptions must not be silently ignored

● MEDIUM

Empty or near-empty CATCH blocks swallow errors silently, masking bugs and security failures. Every catch block must perform meaningful handling — logging the error, notifying the user, or performing cleanup. A catch block containing only a Return is not considered adequate handling.

Non-compliant 
TRY
  id = string(acos(ld_num1))
CATCH (runtimeerror er)
  // empty — error silently swallowed
  Return id
FINALLY
  id = "id"
  Return ""
END TRY
Compliant 
TRY
  id = string(acos(ld_num1))
CATCH (runtimeerror er)
  MessageBox("Runtime Error", er.GetMessage())
  Return id
FINALLY
  id = "id"
  Return ""
END TRY
09

IP addresses must not be hardcoded

● MEDIUM

Hardcoded IP addresses in compiled binaries can be extracted through decompilation and reveal internal network topology to attackers. They also create maintenance burden and break deployments across environments. Store addresses in configuration files, environment variables, or a secrets manager.

Non-compliant 
String ls_ip
String ls_ipv6

ls_ip   = "127.0.0.1"             // hardcoded IPv4
ls_ipv6 = "2001:cdba::3257:9652"  // hardcoded IPv6
ls_ip   = testIP("2.2.2.2")       // hardcoded as argument
Return  testGlobalIP("1.1.1.1")  // hardcoded in return
10

User IDs and passwords must not be hardcoded

● HIGH

Hardcoded credentials in executable files can be recovered through decompilation. This violates GDPR, SOX, and HIPAA when the exposed data is regulated. Credentials must always be retrieved at runtime from secure storage — user input, encrypted config, or a secrets vault.

Non-compliant 
// Password and UID baked into connection string
DBParm = "ConnectString='DSN=Sales;" &
  + "UID=dba@123;PWD=sql1$12'"
Compliant 
// Credentials from user input at runtime
DBParm = "ConnectString='DSN=Sales;" &
  + "UID=" + txtUserId.Text &
  + ";PWD=" + txtPassword.Text + "'"
11

User input must not allow path traversal attacks

● HIGH

When file paths are constructed from user-supplied data (URL parameters, form fields, cookies), an attacker can inject sequences like ../ to escape the intended directory and access, modify, or delete arbitrary files on the server. Validate all path inputs against a whitelist of allowed paths or characters before passing to file system functions.

Non-compliant 
global function string testDelete (string docname)
  boolean lb_exist
  lb_exist = FileExists(docname)   // unsanitized user input
  FileDelete(docname)              // path traversal possible
  helper.FileDelete(docname)
  Return docname
end function
12

OS commands must not be constructed from user input

● HIGH

Passing unsanitized user input to Run() allows command injection — an attacker can terminate the intended command and execute arbitrary OS commands. Use a fixed command whitelist and never concatenate user-controlled values into shell commands. Strip all shell metacharacters if dynamic arguments are unavoidable.

Non-compliant 
global function string callRun (string name)
  Run(name)   // arbitrary command from input
  Return name
end function
Compliant 
global function string callRun (string name)
  Run("MYBATCH.BAT TEST")  // fixed command
  Return name
end function
13

Regular expressions must not be generated from user input (ReDoS)

● MEDIUM

ReDoS (Regular Expression Denial of Service) occurs when a regex engine is forced into catastrophic backtracking by a crafted input. If the regex pattern itself is user-supplied, an attacker can craft a pattern that consumes 100% CPU indefinitely. Always use hardcoded, pre-validated patterns — never build patterns from user data.

Non-compliant 
global function string matchTest (string regPattern)
  string findtext = "Ola Mundo"
  Match(findtext, regPattern)  // user-controlled pattern
  Return regPattern
end function
Compliant 
global function string matchTest (string regPattern)
  Match("hi test123", "^[A-Za-z]")  // hardcoded pattern
  Return regPattern
end function
14

Cryptographic hashes must not use SHA-1 or MD-family algorithms

● HIGH

MD5, MD4, MD2 and SHA-1 are all considered cryptographically broken. Collision attacks against MD5 and SHA-1 have been demonstrated in practice. Use SHA-256 or SHA-3 for general hashing. For password storage, use a dedicated KDF such as bcrypt, scrypt, or Argon2.

Non-compliant 
CrypterObject lnv_CrypterObject
lnv_CrypterObject = Create CrypterObject

// MD5 — broken, do not use
lblb_hash = lnv_CrypterObject.MD5(lblb_data)

// SHA-1 — broken, do not use
lblb_hash = lnv_CrypterObject.SHA(SHA1!, lblb_data)
Compliant 
CrypterObject lnv_CrypterObject
lnv_CrypterObject = Create CrypterObject

// SHA-256 — current minimum standard
lblb_hash = lnv_CrypterObject.SHA(SHA256!, lblb_data)

ls_result = string(lblb_hash, EncodingANSI!)
15

SOAP and INET objects must not be used

● HIGH

The legacy PowerBuilder SOAP and INET objects do not support TLS 1.2 or TLS 1.3, making all HTTP/web service communication over these objects vulnerable to protocol downgrade and man-in-the-middle attacks. Replace all usages with the modern HTTPClient object, which supports current TLS versions.

Non-compliant 
// Legacy INET — no TLS 1.2/1.3 support
inet iinet_base
iinet_base = CREATE inet
li_rc = iinet_base.HyperlinkToURL( &
  "https://www.example.com")

// Legacy SOAP — same TLS limitation
SoapConnection soapConn
soapConn = create SoapConnection
Compliant 
// HTTPClient — supports TLS 1.2 / 1.3
httpclient ve_client
ve_li_ret = ve_client.sendrequest( &
  "GET", "https://www.example.com")

if ve_li_ret > 0 then
  ve_client.getresponsebody(ls_json)
end if
