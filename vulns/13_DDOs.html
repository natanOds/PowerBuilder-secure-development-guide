Expressões regulares não devem permitir ataques de negação de serviço

Descrição da regra

  • É altamente desaconselhável gerar expressões regulares a partir de dados do usuário, porque isso pode levar à negação de serviço de expressão regular (ReDoS). Esse tipo de ataque explora a possibilidade de que a maioria das implementações de expressão possam atingir situações extremas, diminuindo drasticamente sua velocidade. Um invasor pode induzir essa situação quando um programa usa uma expressão regular e a bloqueia por muito tempo (daí a negação de serviço).


Exemplo de código não compatível global function string matchRegexTest2 (string regPattern)
string findtext
findtext = "Ola Mundo"
Match(findtext, regPattern)
Return regPattern
end function

Exemplo de código compatível global function string matchRegexTest1 (string regPattern)
Match("hi test123", "^[A-Za-z]")
Return regPattern
end function
