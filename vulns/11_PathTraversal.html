A entrada do usuário não deve permitir injeção de caminho ou ataques transversais de caminho

Descrição da regra

  • Os dados inseridos pelos usuários, como parâmetros de URL ou cookies, devem ser considerados suspeitos. Se o seu código gerar dinamicamente um caminho do sistema de arquivos a partir desses dados, um hacker poderá injetar valores específicos como '../' e alterar o caminho pretendido originalmente.
  • Esses ataques são frequentemente chamados de "travessia de caminho" ou "travessia de diretório". Eles permitem que o invasor acesse diretórios proibidos para ler, modificar ou excluir dados confidenciais ou executar comandos do sistema operacional.
  • Identificar o código que apresenta essas vulnerabilidades para permitir que você o limpe.
  • Uma possível estratégia de defesa consiste em definir uma lista branca de caminhos ou personagens autorizados.
